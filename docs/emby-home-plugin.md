# 首页插件指南

通用插件模型（目录与包、执行模型、通道与动作调用、webui 与门禁、缓存分工）见
[plugin-contract.md](plugin-contract.md)；本文只讲**首页这一类**的行与条目规范。

首页插件是 `home` 类型插件，与元数据插件、源插件共用同一套宿主与生命周期（安装、启停、动作调用、
自带 webui 都由统一宿主处理）。它对外提供的是**行**：一行 = 客户端上的一个媒体库，
行内容就是那个库里的条目。

配套：Emby 端点兼容规矩见 [emby-compat.md](https://github.com/dlushu/media-bridge-panel/blob/main/docs/emby-compat.md)。

---

## 一、定位与边界

- 插件是数据的生产者：声明若干行，每行各自决定内容从哪来。
- 面板是宿主与中介：把 Emby 端点上的请求转成对插件的动作调用，再把条目转成 Emby DTO。
- 一行 = 客户端媒体库列表里的一个库；客户端点进库就来要这一行的内容。

边界：

- **插件没有回调面板的通道**。宿主给插件的上下文只有 `type`（自己是谁）、`id`、`dataDir`
  （自己的数据目录）、`log`（写面板日志）四样；插件之间也不能互相调用。
- 因此首页插件取数要用的凭据（例如上游 token）**由插件自己存、自己带**，面板不代做也不下发。
- 不属于本规范的东西：条目详情、季集、播放、账号与握手，由面板的 emby 层自己做，见
  [emby-compat.md](https://github.com/dlushu/media-bridge-panel/blob/main/docs/emby-compat.md)。

## 二、动作契约

首页插件向宿主申报两个动作，动作名与入参出参由本规范固定。

### `rows`（申报行清单）

无入参，回：

```
{ ok: true, rows: [ { id, title, collectionType?, feed? }, … ] }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 行 id，形状 `^[a-z0-9][a-z0-9._-]{0,63}$` |
| `title` | 是 | 显示名，用作客户端里的媒体库名 |
| `collectionType` | — | 这个库是哪种库：`movies` / `tvshows` / `mixed` |
| `feed` | — | 声明这一行接客户端的哪一类推荐查询 |

面板把 `rows` 的结果存一份**内存快照**（5 秒保鲜，过期后由后台异步再刷一次），
所以改行参数后最迟几秒反映到客户端的媒体库列表上。

**`collectionType`** 的取值顺序：行声明 → 按该行当前的 `type` 参数推
（`movie`→`movies`、`tv`→`tvshows`）→ `mixed`。规则：

- 有 `type` 参数的行**不写** —— 用户把参数切到"剧集"，库就该跟着变成剧库，写死反而错；
- 没有 `type` 参数、内容类型确定的**要写**（例：按 `with_networks` 筛剧的行 ⇒ `tvshows`）——
  这一条只有插件作者说得准；
- 天生混装的写 `mixed`（例：片单里影剧混装）。

不写也没有对错，只是那个库在客户端眼里是"混合库"。

**`feed`**：有些客户端要推荐**不带库 Id**，直接发一条 `SortBy` 描述。声明 `feed` 之后，
面板把那条查询路由到这一行（取第一个声明的行）。**没有任何行声明 `feed` 时，那条查询如实回空** ——
面板不猜、不随便挑一行顶上。

### `run`（跑一行）

入参 `{ rowId, params?, startIndex?, limit? }`，回 `{ items, total, cached? }`：

| 字段 | 说明 |
|---|---|
| `items` | HomeItem 数组，见第四节 |
| `total` | 这个库的总条数；插件不知道就按本页条数如实报 |
| `cached` | 可选，这次是否命中插件自己的缓存 |

- **分页原样透传**：`startIndex` / `limit` 是客户端请求里的原值，原样交给插件。取哪一页、
  要不要按页打上游由插件决定，面板与插件层**都不切片**。
- ⚠️ **但一页必须按窗口填满**：客户端拿到 `items` 少于 `limit`，就当成最后一页、**不再翻页**
  （SenPlayer 6.2.1 实测如此）。上游一页往往只有 20 条（好多站就是），只取第 1 页来填 `limit=30`
  会让第 2 页永远拿不到。所以 `run` 要**按 `startIndex`+`limit` 连续取上游页**（够数或上游给空
  为止），再从累积结果里切出这一页。**不能假定客户端会按实际条数往后推进**（Rex 能容错，SenPlayer 不能）。
- `total` 会成为客户端看到的 `TotalRecordCount`，客户端靠它决定还能不能往下翻；
  不给就按本页条数报，客户端认为翻不动。
- **失败照实失败**：面板把失败原样转成客户端的失败码并记日志，不编空数据、不静默回退。

### 行结果缓存

行结果缓存归插件自己（契约第十节）。行声明里的 `cacheDuration`（秒，`0` = 不缓存）由插件执行。

## 三、行声明

行除上表的 `id` / `title` / `collectionType` / `feed` 之外，还可带：

| 字段 | 说明 |
|---|---|
| `cacheDuration` | 结果缓存秒数；`0` 或缺省 = 不缓存 |
| `params` | 用户可配参数 |

`params` 每项是 `{ name, title, type, value?, … }`：

| `type` | 控件 | 说明 |
|---|---|---|
| `enumeration` | 下拉框 | 必须给 `enumOptions: [{ title, value }]` |
| `count` | 数字框 | `value` 为默认值 |
| `input` | 文本框 | `value` 为默认值；可带 `description`（占位提示）与 `placeholders: [{ title, value }]`（候选值） |

参数的声明、存储、读取都归插件自己（都在插件自己的数据目录下）。

## 四、HomeItem

面板侧负责**严格归一化**：**只保留下表字段，其余一律丢弃**。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定唯一键，行内去重按它 |
| `type` | 是 | `movie` \| `tv`（其它值整条丢弃） |
| `title` | 是 | |
| `originalTitle` | — | 原名 |
| `year` | — | 数字；`0` 或非法丢弃 |
| `overview` | — | 简介 |
| `rating` | — | 数字；`0` 或非法丢弃 |
| `poster` | — | 完整 http(s) URL |
| `backdrop` | — | 完整 http(s) URL，横图 |
| `genres` | — | 字符串数组（最多 20 个） |
| `providerIds` | — | 对象，如 `{ <域>: "<编号>" }` |
| `catpaw` | — | `{ site, vodId }` |

丢字段的规矩：

- 规范外的字段**一律丢掉**（含 `poster` / `backdrop` 不是 http(s) URL 的情况）；
- 缺 `id` / `title`、或 `type` 不是 `movie` / `tv` 的条目**直接丢**；
- 单行内 `id` 重复只留第一条；每行最多留 200 条，超出与丢弃都计数。

条目 `id` 的字形不强制，但建议用面板能反查的坐标（形状 `{域}_{编号}_{movie|tv}`）：
客户端点进这一条时会拿它去要详情，面板按坐标反查。自编的 id 照样显示，点进去没有资源。

## 五、与 Emby 端点的接线

列表数据由首页插件决定，面板的 emby 层做中介 —— 只负责端点映射与 DTO 转换。

**媒体库 Id 由面板生成**：`catpawhome_` + base64url(`<插件id>|<行id>`)。
稳定性由面板保证（行不变则 Id 不变），插件看不到也不需要管这个 Id。

| 端点 | 说明 |
|---|---|
| `Views` | 每个启用插件里启用的行 = 一个媒体库，`Id = catpawhome_…`、`Type = CollectionFolder` |
| `Items?ParentId=<库Id>` | 跑对应那一行 → 条目转成 `BaseItemDto`；`StartIndex` / `Limit` 原样透传给插件；插件的 `total` 直接当 `TotalRecordCount` |
| `Items/Latest?ParentId=<库Id>` | 同上跑那一行，回裸数组（协议如此），`Limit` 缺省 20；顺序由插件决定 |
| 「推荐」查询（无 `ParentId`，`SortBy=IsFavoriteOrLiked,…`） | 按 `feed` 路由到声明了该 `feed` 的行；没有行声明就如实回空 |
| 库封面 | 只从"这一行**已经取到过的条目**"里取一张图；**不为封面单独打上游** |
| 图片 | 客户端要图走面板的**图片端点**：面板把条目的海报 / 背景地址编成签名 tag 或记入本地索引，两条路都是 0 上游调用 |

条目详情、季集、播放、账号与握手都不归首页插件管，见 [emby-compat.md](https://github.com/dlushu/media-bridge-panel/blob/main/docs/emby-compat.md)。

## 六、参考实现

本仓库内置一个**首页示例插件**：若干榜单行（趋势 / 高分 / 分类 / 播出平台 / 出品公司 /
片单 / 近一月地区剧集 · 综艺 / 随机推荐等）。它是本类插件的完整样例，几部分各占一块：

| 部分 | 作用 |
|---|---|
| 包声明 | `type: home`、入口 `index.js`、webui `ui/index.html` |
| 动作层 | `rows` / `run` / `http`，参数合并、结果缓存与单飞、分页透传 |
| 行清单与行处理器 | 行声明、逐行取数与归一化 |
| 上游客户端与通用请求 | 打上游、超时与失败如实抛 |
| 设置与私有存储 | 自己的设置与缓存，落在自己的数据目录下 |
| 自带 webui | 填上游 token / 语言 / API 基地址 / 图片基地址，以及逐行编辑行参数 |

token 与行参数都由这个插件自己存（落在它自己的数据目录），取数时自己带上。

设置入口在面板的「插件 → 管理」页那一行的「设置」按钮，点开就是插件的自带 webui。

## 七、铁律

1. **不编假数据**：插件给不了或这次取失败，就照实失败；面板如实留空并点名，不猜、不静默。
2. **归一化严格**：规范外的字段丢掉，缺关键字段的条目丢掉（见第四节）。
3. **未发布的兼容不留**：契约、字段名、动作名该改就改，不为旧形态留兼容分支。
4. **面板不猜**：行内容归插件，面板只按规范调用与转换。
