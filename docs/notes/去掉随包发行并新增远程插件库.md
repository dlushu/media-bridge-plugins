# 去掉「随包发行」并新增远程插件库

## 一、摘要

两件事一起做：

1. **去掉「随包发行（builtin）」概念** —— 面板不再开机把仓库里 `plugins/` 的插件同步进数据目录，
   不再有 `origin:'builtin'`、不再有 `/api/plugins` 的 `builtins[]`。**全新安装的面板是空的（零插件）。**
2. **新增「插件库」** —— 插件全部打包推到**独立仓库** `dlushu/media-bridge-plugins`（只放包 + 清单，
   不放源码），面板「插件 → 插件库」页拉该仓库的 `index.json` 列出可安装插件，一键装。
   手动上传 `.tar.gz` 的既有能力原样保留在「插件 → 管理」页。

### 为什么这么做

用户实测的 bug：卸载内置插件 `source/<id>` 当场成功（DELETE 200、目录删除、日志「插件已卸载」），
**但重启后面板又把它装回来并启动了**（日志「✔ 内置插件 source/<id>：已装入 v1.0.0」、pid 49 启动、目录恢复）。

根因在 [store.js](file:///Volumes/dav/Device/GL/user/disk1_part1/docker-compose/catpaw-panel/server/modules/plugin/store.js) 的
`syncBuiltins()`：开机扫仓库 `<repo>/plugins/`，按内容指纹把内置插件同步进 `data/plugins/`
（首次同步即 `enabled:true`）。这既让「卸载」按钮的承诺不成立
（[plugin-contract.md L61-63](file:///Volumes/dav/Device/GL/user/disk1_part1/docker-compose/catpaw-panel/docs/plugin-contract.md)
本来就写着「卸载一个内置插件只在本次运行内有效」），也和「面板只是个中立的宿主」这一定位冲突。

用户决定的口径：**去掉随包发行，插件改成从独立仓库装，全新安装就是空的。**

## 三、目标形态

```
面板仓库 dlushu/media-bridge-panel（源码 + 开发用）
  plugins/<类型>/<id>/            ← 插件**源码**（开发用，仍留在面板仓库）
  tools/plugin-pack.js            ← 新增：把 plugins/ 打成包 + 生成清单
       │  --out <插件仓库的 clone 目录>
       ▼
插件包仓库 dlushu/media-bridge-plugins（不放源码）
  index.json                      ← 清单（有哪些插件、什么版本、包在哪、包 md5）
  packages/<类型>/<id>/<id>-<版本>.tar.gz
       │  raw.githubusercontent.com 直取
       ▼
面板「插件 → 插件库」页 → 下载 → 两道校验 → 安装（origin:'library'）
面板「插件 → 管理」页 → 手动上传 .tar.gz（origin:'manual'）—— 既有能力不动
```

```js
const LIBRARY_REPO = String(process.env.PLUGIN_REPO || 'dlushu/media-bridge-plugins').trim();

```

对外三个函数：

| 函数                        | 做什么                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `index({ force })`        | 取清单（60 秒缓存，失败不缓存）→ 标注每个插件的已装状态 → 返回 `{ repo, repoUrl, indexUrl, generatedAt, fetchedAt, plugins[], bad[], error }`。取不到时 **不抛**，把原因放进 `error`（与 `/api/panel/update` 同口径，页面内联显示） |
| `find(type, id, version)` | 在清单里找一条（支持点名版本）；找不到回 `null`                                                                                                                                                    |
| `download(entry)`         | 取包字节 → **第一道 md5 校验**（对不上当场抛）→ 大小上限沿用 `contract.MAX_BYTES`                                                                                                                     |

* 清单校验：`schema === 1`，`plugins` 是数组；每条必须有 `type / id / name / version / path / md5 / bytes`，
  且 `type` ∈ `contract.TYPES`。**不合规的条目进** **`bad[]`（如实点名），不连累整份清单**。

* 标注逻辑：`installed`（在 `store.list()` 里有没有）、`installedVersion`、`hasUpdate`
  （比较版本号，`library.js` 内自带一个 3 行的 `compareVersion`）、`installedOrigin`。

* `fetchBytes(url, { what })`：与 update.js L283 同款 —— 支持 `http(s)://` 与本地路径，
  `redirect:'follow'`，`user-agent: media-bridge-panel`。

* `sourceUrlOf(entry)`：默认 `raw(entry.path)`；`PLUGIN_SOURCE_URL` 可覆盖，
  占位符 `{repo}` `{path}` `{type}` `{id}` `{version}` —— 给镜像/内网留口子（同 `APP_SOURCE_URL` 的用法）。

**B3.** **[router](file:///Volumes/dav/Device/GL/user/disk1_part1/docker-compose/catpaw-panel/server/modules/plugin/routes.js)** **加两个端点**

### D. 打包脚本

**D1. 新增** **[tools/plugin-pack.js](file:///Volumes/dav/Device/GL/user/disk1_part1/docker-compose/catpaw-panel/tools/)**

用法：`node tools/plugin-pack.js --out <插件仓库的 clone 目录>`

1. 扫 `plugins/<type>/<id>/plugin.json`（`type` ∈ `contract.TYPES`），对每个包**先** **`contract.readManifest`** **校验**
   （不合规的当场报错退出，不产出半份清单）。
2. 把插件目录复制到临时目录（**跳过** **`data/`** **与隐藏文件** —— 复用 `contract.walk` 的同一套口径）。
3. **注入第二道校验**：算出复制件的 `{ 相对路径: md5 }`（**不含** **`plugin.json`** **自己，无法自校验**），
   与原声明合并后重写 `plugin.json`。这样包里的 `files` 声明是真的，`readManifest` 的逐文件核对才生效
   （契约 L57 早就留了这个字段，一直没人填）。
4. 打包：`tar -czf <out>/packages/<type>/<id>/<id>-<version>.tar.gz -C <复制件> .`
   （顶层即包内容，无多余嵌套；`extractToTemp` 也认多一层）。
5. 算这个 tar.gz 的 md5 与字节数 → 清单条目。
6. 写 `<out>/index.json`。**先清掉** **`<out>/packages/`** **与** **`index.json`** **再重建**（确定性产物；
   `.git` 一概不碰），最后打印一张表（类型/id/版本/文件数/字节/md5 前 8 位）。

`index.json` 的形状（写进契约，见 F1）：

```json
{
  "schema": 1,
  "generatedAt": "2026-09-28T12:00:00.000Z",
  "plugins": [
    {
      "type": "source", "id": "<id>", "name": "<插件名>", "version": "1.0.0",
      "description": "…", "domain": "", "hasWebui": true, "depends": [],
      "bytes": 12345, "md5": "…",
      "path": "packages/source/<id>/<id>-1.0.0.tar.gz"
    }
  ]
}
```

`plugins` 按 `type` → `id` 排序（产物可比对、diff 稳定）。

## 五、决策与假设

| # | 决策/假设                                                          | 依据                                                                |
| - | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1 | 面板仓库的 `plugins/` **源码目录保留**                                    | 用户只说「包仓库不放源码」。打包脚本要读它，且它是唯一开发入口                                   |
| 2 | 插件库地址用**常量 + 环境变量覆盖**，不做成面板设置页里的输入框                            | 与 `APP_REPO`/`APP_SOURCE_URL` 完全同款；少一个可配错的地方                      |
| 3 | 插件库安装的 `origin` 记为 `'library'`，手动上传记为 `'manual'`（原 `'upload'`） | 两者都从 `installDir` 的 `origin` 默认值/调用方给定；不写后端迁移（ADR-0034 的「不做迁移」口径） |
| 4 | 手动安装卡**留在「管理」页**，不搬到「插件库」页                                     | 只做被要求的事；搬动会让「管理」页失去装插件入口                                          |
| 5 | 打包时**注入** **`files`** **逐文件 md5**                              | 契约 L57 早有此字段却从没人填；库安装是「信任远端」的场景，第二道校验该生效                          |
| 6 | 清单取不到时 `GET /api/plugins/library` 仍回 **200 +** **`error`**     | 与 `/api/panel/update` 同口径：页面内联显示，不弹 toast                         |
| 7 | 标签页命名为「插件库」，挂在「插件」模块下（`插件 → 管理 / 插件库`）                         | 与既有「插件 → 管理」并列，改动最小                                               |
| 8 | 生产 `app/1.3.5-plug/plugins/` 目录**不删**                          | 改完代码后没人读它；删生产卷上的目录是无收益的破坏性操作                                      |
| 9 | 不为了「内置」留任何兼容分支                                                 | 契约总则「不为未发布的东西留兼容」                                                 |
