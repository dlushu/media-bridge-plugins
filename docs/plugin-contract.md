## 一、定位与边界

| 角色 | 是什么 |
|---|---|
| **插件** | 一个可安装、可卸载的包，跑在自己的常驻子进程里，提供若干**动作** |
| **面板** | 宿主：安装校验、启停、把请求转成"对插件的动作调用"、把结果转成 Emby DTO 或页面数据 |
| **模板** | 一份配置数据文件（站点集合 + 打分过滤参数），按**域**被选用 |

**铁律（与项目既有取向一致）**

1. **不编数据**：插件给不了、或这次取失败，面板一律**如实留空并点名**，不猜、不静默。
2. **面板不解释插件的数据**：动作的入参出参由本文规定；插件内部怎么取数、怎么组织，面板不关心。
3. **不为未发布的东西留兼容**：契约、字段名、动作名该改就改，不留双读分支。

## 二、插件的身份与目录

- **类型**：`metadata`（元数据）、`source`（源）、`home`（首页插件）、`output`（输出：给外部播放器/外部消费方的出口插件）。
- **身份** = `(类型, 插件 id)`。同一个 `id` 在不同类型下是两个插件，互不冲突。
- **目录布局**（都在数据目录下）：

  ```
  plugins/<类型>/<插件 id>/          包本体（代码 + 自带 webui 静态文件 + 声明文件）
  plugins/<类型>/<插件 id>/data/     插件自己的数据目录（设置与缓存都在这里）
  ```

- **包**：一个 `tar.gz`。安装 = 解到 `plugins/<类型>/<id>/`（解出来的目录多一层也认）。
  **两道校验**（与源包同一套，见 [ADR-0015](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0015-source-bundle-integrity.md)）：
  ① 包本身的 md5（发布方给的那个，可省）；② 清单里 `files` 声明的**逐个文件** md5。
  任一道对不上就**当场拒绝**，不"先装上再说"、也不拿实际值去覆写清单假装成功。
- **包里的 `plugin.json`**（缺它装不上）：

  | 字段 | 必填 | 说明 |
  |---|---|---|
  | `id` | 是 | 反向域名风格，**同一类型内唯一**（身份 = `(类型, id)`） |
  | `name` | 是 | 显示名 |
  | `version` | 是 | 版本 |
  | `type` | 是 | `metadata` / `source` / `home` / `output` |
  | `main` | — | 入口文件，默认 `index.js` |
  | `domain` | 元数据插件必填 | 它注册的**域 id**（条目 Id 的前缀，见 [ADR-0031](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0031-metadata-by-domain.md)） |
  | `series` | — | 元数据插件：剧集式（默认 `true`）还是电影式 |
  | `webui` | — | webui 入口（相对包目录，如 `ui/index.html`） |
  | `files` | — | `{ 相对路径: md5 }` —— 给了就逐文件核对（第二道校验） |
  | `depends` | — | 依赖的域 id 或 `类型:id`；**缺依赖如实失败并点名**，不半启动 |
  | `ingress` | — | 外部 HTTP 入口的鉴权声明 `{ public: [], token: [] }`，只对 `ui/**`、`api/**` 两条路径生效；缺省全走面板登录门禁。写法与语义见第十一节 |
  | `updateUrl` | — | **插件自更新清单**地址（http(s)，Magisk 式，见下）；不写就只能从插件库更新 |
  | `description` | — | 一句话说明 |
  | `author` | — | 作者署名（插件库与管理页里显示；不写就不显示这一行） |

- **插件不随面板发行**：面板的 Release 包里**只有面板本体**，装完是**零插件** ——
  插件从**插件仓库**（默认 `dlushu/media-bridge-plugins`，可用 `PLUGIN_REPO` 换）的「插件库」页安装，
  或者在管理页上传一个 `.tar.gz` 手装（见下）。仓库里**只收打好的包与清单**，不收插件源码。
- **卸载是真的卸掉**：进程停掉、目录删掉，重启之后面板**不会**把它装回来
  （原先的开机同步内置插件已删除，见 [ADR-0035](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0035-plugin-library.md)）。
- **插件的设置与缓存都由插件自己管**（都在它自己的 `data/` 下）。面板里的"清空插件数据"
  就是**删这个目录**。

### 插件从哪来：插件库与手动安装

两条来路，做的都是"解一个 `tar.gz` 装进 `plugins/<类型>/<id>/`"，区别只在包从哪来。

| 来路 | 入口 | 包从哪来 | 记的 `origin` |
|---|---|---|---|
| **插件库** | 「插件」栏的「插件库」页 | 插件仓库的清单与包 | `library` |
| **手动安装** | 「插件」栏的「管理」页 | 本地上传的 `.tar.gz` | `manual` |

- **清单**：插件仓库根目录一个 `index.json`（`schema: 1`），逐条给出 `type` / `id` / `name` /
  `author` / `version` / `description` / `domain` / `hasWebui` / `depends` / `bytes` / `md5` / `path`。
  `path` 形如 `packages/<类型>/<id>/<id>-<版本>.tar.gz`。面板拉它是为了**列出来供挑**；
  **拉不到就如实报错**（页面把原因写出来），不静默回退到内置列表。
- **列表**：`GET /api/plugins/library`（带 `?refresh=1` 绕过 60 秒缓存重拉清单）。
  每条会标出 `installed` / `installedVersion` / `installedOrigin` / `hasUpdate` / `sourceUrl`。
- **安装**：`POST /api/plugins/library/install`，body `{ type, id, version?, enable? }` ——
  按清单里的 `path` 取包，走**同一套两道校验**装进数据目录；`enable` 为真则装完就启用。
- **包怎么来的**：由本仓库的 `tools/plugin-pack.js` 产出 ——
  它把 `plugins/<类型>/<id>/` 打成一个 `tar.gz`，**顺手把 `files`（逐文件 md5）注入包里的 `plugin.json`**
  （手写的清单里没人声明 `files`，第二道校验原先形同虚设），随后写出 `index.json`。
  ⇒ 插件源码留在本仓库本地（`plugins/` 不进版本库），版本库里只收**产物**。

### 插件自更新（Magisk 式 `updateUrl`）

除了插件库，插件还能**自己声明去哪查新版** —— 和 Magisk 模块在模块里写更新地址同一个路子：

1. 插件在 `plugin.json` 写 `updateUrl`，指向一个自己的小清单（http(s)）。本仓库插件默认指向
   `packages/<类型>/<id>/update.json`，`plugin-pack.js` 打包时**自动生成**这个文件（与包同目录）。
2. 清单形状：

   ```json
   { "version": "1.0.2",
     "url": "fwrex-1.0.2.tar.gz",
     "md5": "（可选；包整体 md5，给了就当第一道校验）",
     "changelog": "（可选；一句话更新说明）" }
   ```

   `url` 可以写绝对 http(s) 地址，也可以写**同目录文件名**（打包工具默认这么写，
   面板按 `updateUrl` 所在目录解析），换成别的托管镜像也不用改包。
3. 管理页对声明了 `updateUrl` 的插件显示「更新」按钮：`GET /api/plugins/<类型>/<id>/update-check`
   查清单（60 秒缓存，`?refresh=1` 绕过），有新版时确认后 `POST /api/plugins/<类型>/<id>/update`
   一键下载换装。**插件库（`index.json`）不参与这条链路**，包没被任何仓库收录也能自更新。
4. **自动查 + 一键全更**：管理页打开时自动查一遍，之后每 5 分钟再查（页面关掉就停），
   查出新版的插件在行里标「可更新 vX」、按钮变成「更新到 vX」，卡头那颗「全部更新（N）」
   一次把有新版的都装上（**串行**，每次更新都要停旧起新；中途失败不打断后面的，最后一起报）。
   批量查走 `GET /api/plugins/updates`（一次查完所有声明了 `updateUrl` 的已装插件，单个失败
   不牵连其余，结果里带 `error`）。装完覆盖安装的那条 60 秒缓存会被作废，页面立刻显示新版本。
5. 安全口径：`updateUrl` 与清单里的 `url` 都只收 http(s)（相对文件名解析完也必须是 http(s)）；
   下载的包仍走**同一套两道 md5 校验**；更新包的 `(类型, id)` 必须与已装插件一致、
   清单声明的版本必须与包内 `plugin.json` 一致 —— 不允许借"更新"把包换成另一个身份。
6. **装完自动重启**：覆盖安装（手动上传 / 插件库更新 / 自更新，三条路同一套）会先等旧进程真的退出、
   换新包，再按原来的启用状态把新进程起回来；原来没启用的装完仍不启用。

## 三、执行模型

- 插件**跑在自己的常驻子进程**里，由面板启动与停止。
- **不沙箱**：插件能读写自己的目录、能联网、能起进程 —— 与"像 Linux 装包"同一个模型
  （权限前提与风险见 [ADR-0028](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0028-plugin-system.md)）。
- **"面板停、插件就停"由宿主保证**：子进程属于面板，面板退出时直接终止它们，不依赖插件配合。
- 插件**自己**再起的东西（例如源插件内部部署的实例）必须在收到停止指令时自行清理，
  否则会变成孤儿进程、继续占着端口。
- 面板要管 N 个进程（启停、健康、日志；**进程崩了只记账、不自动重启**）。这层复用现有源托管的做法
  （启动 / 嗅探端口 / 留尾部日志 / 停止）。

## 四、面板与插件之间的通道

- 走**管道**（Node 的 child IPC；非 Node 插件可用"stdin/stdout 每行一条 JSON"）。
  **不占端口**、**不用鉴权**（只有父子能碰）、更快。既有实现见首页插件的宿主
  （`job` / `rpc` / `rpcResult` / `done` 消息）。
- **动作名**：走管道之后没有"网址"，端点名就是**一个动作标识**。对比：

  ```
  现状：POST http://<源地址><站点 api>/search   { wd, page }
  之后：{ action: 'search', site: …, wd, page }
  ```

  动作名一律用**语义名**（`站点清单` / `搜索` / `取播放项` / `解析地址` / …），
  不写成 `/config`、`/search` 这类路径样式 —— 免得后来者以为还要发 HTTP。
- 插件**内部**要不要给自己的实例开端口，是插件自己的事；面板不参与分配、也不依赖它。
- 插件入口的形状：`module.exports = { actions: { 动作名: async (args, ctx) => 返回值 } }`。
  `ctx` 给四样东西：`type` / `id`（自己是谁）、`dataDir`（自己的数据目录）、`log(...)`（写进面板日志）、
  `hostCall(target, action, args)`（**反向调用宿主**，白名单制，见下）。
  面板**只做**"把请求转成动作、把返回值转回去"，不做别的（加载与分发由宿主的 `runner.js` 负责）。
- 调试口径：面板把**每次请求与回复写进日志**（沿用现有源"留子进程尾部日志"的做法）。

### 插件反向调用宿主：`ctx.hostCall`

插件之间**仍然不能互相调用**；但 output 这类"出口"插件需要把面板已有的能力（首页榜单、聚合搜索 /
详情 / 播放）转给外部消费方，所以宿主在管道上开了一条**反向通道**，且只暴露**白名单**里的动作：

```
ctx.hostCall(target, action, args) -> Promise<{ ok: true, value } | { ok: false, error: { code, message } }>
```

- 消息形状：插件 → 宿主 `{ type:'hostCall', id, target, action, args }`；
  宿主 → 插件 `{ type:'hostCallReply', id, ok, value? , error? }`（`id` 由插件侧递增、自行配对）。
  30 秒超时，宿主与插件两侧各自计时；宿主不在线 / 管道已断时调用 reject。
- 当前白名单（以宿主代码 `server/modules/plugin/host-api.js` 为准）：

  | target | action | 入参 | value |
  |---|---|---|---|
  | `home` | `plugins` | — | 已装的 `home` 插件清单 `[{id,type,name,enabled,running}]` |
  | `home` | `rows` | `{pluginId}` | 该首页插件申报的行 |
  | `home` | `run` | `{pluginId,rowId,startIndex,limit}` | `{items,total,dropped,dup,cached}`（items 已按 HomeItem 归一化） |
  | `agg` | `sites` | — | 聚合站点清单 |
  | `agg` | `search` | `{domain,keyword,page?}` | 聚合搜索结果 |
  | `agg` | `detail` | `{domain, ...}`（source/site/vodId 快路径，或 name/year；剧集带 `season`/`episode`） | 聚合详情 |
  | `agg` | `play` | `{domain,ref,clientHost?}` | `{urls,header,parse,nonHttp}` |

- 白名单之外的 `target/action` 一律回 `NO_HOSTCALL`；**不转发任意内部调用、不暴露文件系统**。
- output 插件的 `http` 动作应当把 hostCall 的失败码如实映射成 HTTP 状态
  （`BAD_INPUT`/`NO_DOMAIN`/`NO_SITE`/`NO_SOURCE` → 400，`TIMEOUT` → 504，其余 → 502）。

### 输出插件（`output`）

- output 插件**不占端口、不接 Emby**，它就是一个"外部能匿名/持票访问的 HTTP 面 + 一组 hostCall 编排"：
  典型例子是给外部播放器（如 FW/Rex 播放器的 Widget）下发一个脚本，脚本再持**外部访问令牌**
  回头访问本插件的 `api/**`，插件经 hostCall 取首页 / 搜索 / 详情 / 播放。
- 插件自己负责：生成对外产物（脚本 / 配置）、把外部播放器的参数翻译成 hostCall 入参、
  以及把播放结果整理成对方播放器认的形状（直连地址 + `customHeaders`，由对方原生播放器直连 CDN）。
- **令牌绝不编进产物或下载 URL**：匿名产物里只能出现"怎么填令牌"的说明，不能出现明文令牌。

## 五、源插件的动作

> 返回字段在面板与客户端上**长什么样、命名与定位有哪些硬性口径**（实例名 / 候选清洗 /
> 按季集定位 / 版本标签 / 发版自检表），见专门一份：[source-display-rules.md](./source-display-rules.md)。

| 动作（中文名） | 动作 id（代码里用的） | 入参 | 出参 | 必需性 |
|---|---|---|---|---|
| 站点清单 | `sites` | — | `{ sources, sites }`：实例一行一个（含运行态）+ 站点数组 | 必需 |
| 候选 | `search` | 实例 + 站点 key + 搜索词、页码、超时 | 候选列表（+ 上游响应原样） | **仅两层式站点** |
| 取播放项 | `detail` | 实例 + 站点 key + 条目 id + 集号/取法、超时 | 结构化 `detail`：线路 → 选集，每个播放项带 `ref` | 必需 |
| 解析地址 | `play` | `ref` + 客户端主机名、超时 | 真实可直连地址（`{urls, header, parse}`） | 必需 |
| 站点测速 | `probe` | 实例 + 站点 key + 搜索词、超时 | 一发探针的结果 | 必需 |
| webui | `http` | `{method, path, query, body, contentType}` | `{status?, body, contentType?}` | 可选 |

- **线路与选集的解析在插件里**（`$$$` / `#` / `$` 是猫爪源自己的约定；直查那类插件根本没有线路）：
  「取播放项」回来的就是面板要的结构，面板不再解析协议文本。**面板保留**的是"填 Emby DTO"那半件事
  （集名里的规格解析 → `MediaSource` / `MediaStreams`）。
- **播放项上可以多带「规格字段」**，面板读到就填进 Emby 的 `MediaSource`：`container` / `sizeBytes` /
  `width` / `height` / `videoCodec` / `videoProfile` / `bitDepth` / `frameRate` / `videoRange` /
  `audioCodec` / `channelLayout` / `channels` / `atmos` / `bitRate`（体积给**字节数**；视频编码用
  `h264` / `hevc` / `av1` 这类中立名；动态范围用 `DOVI` / `HDR10+` / `HDR10` / `HDR` / `HLG`）。
  **插件给的优先**：面板另外还会从集名里正则猜一份，只有插件没给的项才用猜的兜底 —— 所以知道就给，
  不知道就留空，别填占位值（`0` / `false` / 空串一律算"没给"）。
- **每条线路可以带 `playVia`，声明"这条线路的地址要不要带鉴权头"**：

  | 值 | 含义 | 客户端怎么取 |
  |---|---|---|
  | `'client'`（**缺省**） | 地址**能裸用**：客户端直连即可起播 | 客户端拿 `ref` 走面板的流端点，由面板 302 到真实地址（回环地址由插件按 `clientHost` 换成客户端可达的域名） |
  | `'proxy'` | 地址**必须带一串鉴权头**才取得动（缺了就是 403/断流，头由源给） | 出口插件二选一：① 自己 `play` 取到 `{urls, header}` 并**把头交给客户端**（须宿主支持）；② 把这条线路交回面板的流端点、带上 `playVia=proxy`，由面板**代持头**中继（见面板仓库 [ADR-0042](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0042-auth-line-byte-relay.md)） |

  - **缺省就是 `client`**：不写等于声明"裸用可播"。**面板一律按标注执行，不做类型探测式的兜底** ——
    漏标成 `proxy` 由插件自负（客户端会拿不到头、播不了），标成 `client` 而实际要头同样自负。
  - **`proxy` 的语义是"缺了这串头就播不动"，不是"源顺手给了头"**：源回 `header` 里常有
    信息性的头（`Referer` / `Origin` / 页面 UA），缺了照样能播 —— 那种线路该标 `client`。
    判据只有一条：**这条线路不带头发出去，客户端能不能播**。标错两个方向都吃亏：
    漏标 `proxy` → 客户端拿不到头、播不了；把可裸用的标成 `proxy` → 白白让面板代持流量。
  - **它是声明性标注，不是探测结果**：`detail` 阶段还没有地址可测（地址要 `play` 才拿得到），
    所以这条只能由插件按自己对源的了解写死；一个插件内可以逐条线路不同。
  - **`.m3u8` 之类 HLS 清单**：`client` 线路一样裸用，但客户端不能直接 302（相对路径会失基），
    得走面板流端点的 **200 中继**（把清单里的相对地址补成绝对），依据见面板仓库
    [ADR-0040](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0040-hls-playlist-relay.md)。
  - **把线路交回面板时怎么声明**：面板流端点
    `GET {panel}/api/agg/stream?domain=&ref=&token=` 另认一个 `playVia` 参数（缺省 `client`）；
    出口插件按 `detail` 里那条线路的 `playVia` 原样带上即可。不带 = 面板按 `client` 落（302 / 清单中继）。
  - **面板自己的 Emby 客户端入口（`/api/emby/*`）也按这同一份 `playVia` 落法**，且**不需要插件多传什么**：
    面板拼版本列表时就把该线路的 `playVia` 编进了版本 Id（`MediaSourceId`，读的是 `detail.lines[].playVia`），
    起播时自己取回判档 —— `proxy` 线路在 Emby 里同样由面板**代持头中继**（非清单字节中继 / 清单子地址中继）。
    依据见面板仓库 [ADR-0044](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0044-emby-stream-playvia-relay.md)。
- **`ref` 的形状约定只有一层**：`<插件 id>/<插件自己定的东西>`。面板只按**第一段**路由，
  其余一个字都不解释 —— 它把 `ref` 原样存进 `MediaSourceId`，播放时原样交回来。
  本例（猫爪源）里面是 base64url 的 JSON：实例 / 站点 / 线路 / 条目 id / 集 id / 定位坐标。
- **`clientHost` 为什么要给插件**：本地部署的实例回的是**回环地址**（`127.0.0.1:<端口>`），
  对客户端毫无意义。插件拿它拼成 `http://<客户端访问用的域名>:<实例端口>/…` 再回去 ——
  这一步原来在面板（它当时还知道实例端口），`ref` 转交之后面板不知道了，所以跟着搬进插件。
- **`init` 是插件内部的事**（有的站不先 `POST /init` 就搜不出来）：`search` / `probe` 自己先兜一次，
  按「实例地址 + 站点」记住，并在返回里带 `initCalled` 供面板记日志（诊断用，不参与打分）。
- ⚠️ `站点清单` 里仍带 `url` / `port`，但**只为诊断显示**（插件自己的设置页）——
  面板不再用它们取数、也不再用它改写播放地址。

### 本站点的四个字段（面板只认这四个 + 它自己补的统计）

`source`（**`插件 id / 实例 id`**，站点身份的一半）/ `key` / `name` / `api`。

- **站点身份 = `插件 + 实例 + 站点 key`**：站点 key 只在各自实例内唯一，两个实例都有 `nodejs_muou`
  是常事。面板侧一律用 `插件id/实例id` 这一串当 `source`，所以跨插件也不会撞。
- `api` 只是**诊断显示**用的（插件设置页里那串前缀）；面板不再拿它拼请求。

- **站点数可以是 0**。报 0 个站点的插件在站点表与模板里不出现（等于用不到它）——
  想让自己的插件被用就申报站点，这是插件作者的选择，面板不强制。
- **站点测速**同时回答"通不通"与"快不快"。不另设"探测"动作。
  ⇒ 分工是：**站点清单 = 静态声明有哪些站点；站点测速 = 实测能不能用、多快**。
- **播放项就是"线路"**：**一个名字对应一个地址**。两类站点都遵守这个结构，
  直查那类也**可以有多条**线路。差别只在"怎么取到这些线路"（见下：一层式 / 两层式）。

### 取数式样：一层式与两层式

**聚合的粒度是"版本"，不是"站点"**：对某一部片的某一集（一个元数据坐标），面板只做一件事 ——
向所有该域的站点询问"这一集有哪些可播线路"，能给出的各算一个版本，都不能给就如实空。

| 式样 | 链路 | 面板在中间做什么 | 适合 |
|---|---|---|---|
| **两层式** | 给词 → 候选列表 →（面板打分 / 过滤）→ 取播放项 | 打分与过滤 | 聚合站那类（返回的是候选，不挑就会拿错同名片） |
| **一层式** | 给词 → 直接回播放项列表 | 不做筛选（站点自己保证取准） | 直查那类（给关键词就出地址） |

**打分与过滤留在面板、不搬进插件**（理由见 [ADR-0033](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0033-template-and-domain.md) 的说明）：
它是**跨来源统一的判据**（`match.js` 是"这是不是目标作品"的唯一实现），搬进插件会让判据分叉。
其参数跟着**模板**走。

⚠️ 其中只有一部分参数对**一层式**站点有意义（它们不做筛选）⇒ 设置页要写清
"哪些参数只对两层式站点生效"，免得出现"调了没反应"。

## 六、元数据插件的动作

动作与"面板从上游元数据取用的东西"**一一对应**。

| 动作 | 入参 | 出参 | 必需性 |
|---|---|---|---|
| 注册 | — | 域 id + 能力清单 + 剧集式 / 电影式 + 条目外链模板 | 必需 |
| 取元数据 | 条目坐标（一次一个） | 规范字段 + 成败 | 必需 |
| 取一季分集 | 条目坐标 + 季号 | 分集列表 | 必需 |
| 搜索 | 搜索词 | 候选列表 | 必需 |
| webui | — | 静态文件 | 可选 |

### "取元数据"要提供的字段（按用途分组）

- **身份**：条目 id、类型（电影 / 剧集）
- **名字与时间**：主标题、原始标题、年份、首播日期
- **给源站点搜索用的词**（现为 `searchTitle`：主标题没中文时回退中文别名）
- **简介**（面板按长度上限裁剪）
- **图片**：海报、背景，以及详情页用的图集
- **分类**：类型名列表 **与带 id 的类型项**（客户端要能点进"类型"，只给名字点不进去）
- **规模与评分**：季数、评分
- **详情页那一批**：标语、状态、时长、分级、制作公司（**必须带 id**）、制片国家、关键词、
  外部 id（imdb / tvdb / wikidata）、预告、演职、相似推荐

**「相似推荐」每一项给这几个**（面板只读这几个，别的字段面板不认）：`entryId`（本域自己的条目编号）、
`type`、`title`、`year`、`overview`、`communityRating`、`posterPath`、`backdropPath`。
面板把每一项按**本条目的域**拼成条目 Id（客户端据此点进详情），所以它们必须与正常条目同一套编号。
拿不到就**如实回空数组**，别编 —— 少了这一栏客户端只是不显示，编了则会点进一个不存在的条目。

### "取一季分集"要提供的字段

集号、集名、简介、首播、剧照、评分、时长。**拿不到就如实留空**。

### 能力申报

`注册` 时申报**它会哪些、缺哪些**（即上面那两份字段清单 + 剧集式 / 电影式）。
面板按申报决定给客户端什么、缺的如实留空。

### 条目外链申报

`注册` 还可带 `links`：`[{ name, url }]`，给它这个域的条目配"去站点上看"这类外链
（面板把它转成客户端列表项上的外部链接）。

- `url` 是**模板**，两个占位符由面板替换：`{type}` → `movie` / `tv`（Emby 用的口径）、
  `{id}` → 该条目的编号（面板对它做 URL 编码后再填）。
- 例：`[{ name: '站点', url: 'https://<站点>/item/{id}' }]`。
- **面板不认识任何具体站点**：插件不申报就没有这一条，不猜、不兜底；
  条目编号拿不到时也如实不出这一条。
- `name` 与 `url` 缺一即忽略这一项；整个字段缺省即"没有外链"。
- 只放**能从条目编号推出来**的链接（例如站点自己的条目页）。
  需要额外号码的（如 IMDb 的 `tt` 号）走"取元数据"的外部 id，不在这里拼。

⚠️ **不属于插件、不要塞进来**：图片的**代取与签名**（面板为客户端取图，见
[ADR-0013](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0013-image-endpoint-signing.md)）、各类缓存（各自管各自的，见第十节）、
Emby 的 DTO 形状（面板负责转换，见 [ADR-0007](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0007-emby-dto-shape.md)）。

### 条目 Id

**形状由面板统一规定**，插件只提供"条目 id"（它自己的编号）+ 声明是剧集式还是电影式。
坐标的编解码**不下放给插件** —— 否则面板得懂每个域的坐标语法。
理由：条目 Id 与客户端、进度库的键、首页插件的条目契约绑在一起。

## 七、域、首页与分派

- 元数据插件注册一个**域 id**（就是条目 Id 的前缀，形状 `[a-z][a-z0-9]*`）。面板按域名把
  "条目 → 模板 → 站点"连起来。**面板层是元数据插件与源插件之间唯一的连接点**，
  两类插件互不感知。
- **分派**：条目前缀决定用哪个元数据插件。**认不出的前缀 ⇒ 如实空并点名缺哪个插件**
  （不回退到别的域、不猜、不静默）。
- **首页**：首页插件是 `home` 类型插件，与元数据 / 源插件跑在同一套宿主里；
  **一行 = 客户端上的一个媒体库**。已实现两个动作：
  - `rows`（无参）→ `{ ok: true, rows: [ { id, title, collectionType?, feed? } ] }`：
    申报行清单。`collectionType` 是这一行做出来的库类型（`movies` / `tvshows` / `mixed`）；
    `feed` 声明这一行接客户端的哪一类推荐查询，没有行声明时那条查询**如实回空**。
  - `run`（`{ rowId, params?, startIndex?, limit? }`）→ `{ items, total, cached? }`：
    `items` 是 HomeItem 数组，`total` 是这个库的总条数（插件不知道就按本页条数如实报）。
- 行声明的 `id` / `title` / `collectionType` / `feed` 之外，还可带 `cacheDuration`（结果缓存秒数）与
  `params`（用户可配参数，类型 `enumeration` / `count` / `input`）。行的**结果缓存归插件自己**
  （见第十节）。
- **分页原样透传**：`startIndex` / `limit` 是客户端请求里的原值，取哪一页由插件决定，
  面板与插件层都**不切片**。
- ⚠️ **一页必须按客户端窗口填满**（最容易踩的坑）：客户端发来 `startIndex` / `limit` 后，
  **拿到的 `items` 少于 `limit` 就被它判成最后一页，之后再也不来翻页**（SenPlayer 6.2.1 实测如此）。
  上游一页常常只有 20 条（好多站都是），只取第 1 页就填不满客户端常要的 30 / 40 →
  第 2 页永远拿不到。所以插件**必须按窗口连续取上游页**（取到够 `startIndex + limit` 条、
  或上游给空为止），再从累积结果里切出自己这一页。**不能假定"客户端会按实际条数往后推进"** ——
  Rex 那样能容错，SenPlayer 不能。这条对元数据插件的 `search` 同理（面板搜索层按窗口取上游页，
  插件侧只要认 `page` 参数）。
- **媒体库 Id 由面板生成**：`catpawhome_` + base64url(`<插件id>|<行id>`)；稳定性由面板保证，
  插件看不到也不需要管这个 Id。
- **插件没有任意回调面板的通道**：宿主给插件的上下文只有 `type` / `id` / `dataDir` / `log`
  （外加第四节那条**白名单制**的 `ctx.hostCall`，只能调宿主登记过的几个能力），
  插件之间也不能互相调用。因此首页插件取数要用的凭据（例如上游 token）**由插件自己存、自己带**，
  面板不代做也不下发。
- HomeItem 字段表与严格归一化的规矩见 [emby-home-plugin.md](emby-home-plugin.md)。

## 八、播放地址的转交

播放时客户端打的是**面板自己的端点**（本项目的形状是 Emby 那套 `…/videos/{ItemId}/stream`，
版本 Id 里带着 `ref`）。面板把 `ref` 通过管道转给插件，插件回一个**真实可直连地址**，
面板 **302** 过去（面板不扛流量，见 [ADR-0006](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0006-redirect-for-playback.md)）。

- **host 必须是面板**：客户端要能访问那个地址，而面板的端口是已发布、确定可达的；
  插件自己的端口没有发布。客户端因此感知不到插件，也不需要知道插件在哪。
- **只做 302**：插件给不出"客户端可直连的地址"（例如必须带 header / cookie）时，
  面板**如实回"该源需要代理，暂不支持"**，不静默失败。
- **`ref` 由插件输出、插件自己管**：只要内容还在，插件随时能把它换成一个地址
  （可重复解析是**插件的义务**）；地址缓存与有效期也由插件自己处理。
- **面板把「客户端访问用的主机名」一起给插件**（`clientHost`）：本地部署的实例回的是
  `127.0.0.1:<端口>`，那个地址对客户端毫无意义 —— 插件拿它拼成
  `http://<客户端访问用的域名>:<实例端口>/…`（端口原样保留，部署时已发布到宿主）。
  这一步原来是面板在做（它当时还知道实例端口），`ref` 转交之后面板不知道了，所以跟着搬进插件。
- **播放项必须带一个显示名**（聚合站给线路名，直查那类自己决定：片名 / 集号 / 站点名都行）。
  **面板只负责把它传到客户端 —— 不起名、不编**；插件想不出名字就如实留空。

## 九、模板与域

- **模板就是一份配置数据文件**，内容 = **选中的站点 + 打分过滤参数 + 超时与并发**
  （超时与并发也按模板走：不同域的内容、不同的站点，合适的超时本来就不一样）；
  **它自己的 id 就是这套模板的身份**（随机生成、之后固定）。
- **每个域最多一个模板**（一对一）；**一个模板可以被多个域共用**；
- **某个域没有配模板 ⇒ 如实为空并点名**（那个域的内容搜不到；不挑兜底、不猜）；
  **同一个站点可以出现在多个模板里**（站点表要能看出"它被哪几套模板用了"）。
- 站点身份按 **"插件 + 站点 key"** 记，不用端口或实例名之类会变的东西 ——
  插件重装、换端口之后模板照样对得上。

## 十、缓存分工

**两级，各管一段。**

| 位置 | 缓存什么 | 有效期 | 谁决定 |
|---|---|---|---|
| **插件侧** | 它自己的取数结果 | 插件自己定 | 插件（面板不干预） |
| **面板侧** | **这一条目的线路结果**（面板聚合出来的那份） | **按天，默认 1 天**（可改） | 面板设置 |

- 面板侧那份的 `key` 里带上**所有影响结果的参数**（打分参数、线路过滤、模板、站点集合……）⇒
  **改了参数 key 就变、旧结果立即失效**，不需要人工清缓存。
- **判据是"只要有线路就存"**，不要求"所有站点都通"（见 [ADR-0032](https://github.com/dlushu/media-bridge-panel/blob/main/docs/adr/0032-cache-two-levels.md)）。
  代价如实记着：一次"缺了几条线路"的结果会在缓存里留最长一个有效期。
- **插件应当自己缓存，把常见查询做到秒回** —— 这是义务。面板侧那份只挡住
  "客户端点一次播放连问三遍"（几秒内），**超出的热度全压在插件身上**。
- 面板要**按插件记录每次聚合的耗时**（日志 + 统计），否则"慢插件"查不出来。
- 站点级超时与失败跳过按 **"插件 / 注册的站点"** 记账（沿用现有那套逻辑）。
- **测速的归属要分清**：**测速的结果值（站点统计）是面板级共享的一份**，不跟模板走；
  **测速的开关与间隔在面板设置里**。

## 十一、webui、设置与门禁

- 插件的 webui 是**静态文件**，放在插件包里、由面板托管；**插件不提供端口**。
- **导航**：插件注册了 webui 就在导航显示一个入口，"里面是什么"是插件自己的事；
  面板只判断"有没有注册 webui"。入口放在它**所属类型那一栏**下面
  （元数据插件挂「元数据」栏、源插件挂「源」栏）。
  入口是**扫插件目录里的声明文件**发现的（给显示名、排序、指向哪个页面），没有中心注册表 ——
  参照 LuCI 的做法（见第十三节）。
- **设置**：**声明归插件、存储也归插件**（都在插件自己的 `data/` 里）。
- **两条路径**（默认都在 `/api/` 下 ⇒ **受面板登录门禁**；插件可在 `plugin.json` 用
  `ingress` 逐路径放开，见下）：

  | 路径 | 作用 |
  |---|---|
  | `GET /api/plugins/<类型>/<id>/ui/**` | 插件的 webui 静态文件（`/ui/` 之后相对 **webui 入口所在目录**解析，所以页面里 `./x.js` 就是 `ui/x.js`） |
  | `ANY /api/plugins/<类型>/<id>/api/**` | **转发给插件**：面板把这一次请求转成**动作 `http`**（见下） |

- **ingress 声明**（`plugin.json` 可加；不写 = 两条路径都要面板登录 cookie）：

  ```json
  { "ingress": { "public": ["api/widget.js"], "token": ["api/**"] } }
  ```

  - 名单条目是相对路径，形如 `ui/xxx` / `api/xxx`，支持 `*`（单层内任意）与 `/**`（任意层级）；
    写不合法（越界 `..`、绝对路径、别的段名）会在安装时按坏清单拒绝。
  - `public`：**完全匿名**，谁都能访问（只该放不含秘密的静态产物，例如一个脚本）。
  - `token`：要**外部访问令牌**（或有效登录 cookie）。令牌由面板生成
    （`mbp_` + 48 位十六进制；面板设置页可取 / 重置，重置后旧票立即失效），
    三种携带方式等价：query `?token=`、`Authorization: Bearer`、`X-Access-Token` 头。
    对不上或没带 ⇒ 401。`public` 命中优先于 `token`。
  - 两条名单都没命中的路径，照旧走面板登录门禁。
  - **安全口径**：令牌只能证明"有权访问这个插件的 ingress"，不等于面板登录态 ——
    插件经 hostCall 能做的事以宿主白名单为限；秘密（令牌、Cookie）绝不允许编进 `public` 产物。

- **转发用的动作名固定是 `http`**，入参 / 出参：

  ```
  入参  { method, path, query, body, contentType, host, proto }
        · path   = `/api/` 之后的那一段（例如 `/save`）
        · query  = 普通对象（URL query；面板已剥掉用于鉴权的 token 键，不会下发给插件）
        · body   = **UTF-8 字符串**（不是 Buffer；插件侧 JSON.parse(body) 就能用）
        · host/proto = 这次外部请求的 Host 头与协议（output 插件拼自描述地址时用）
  出参  { status?, body, contentType? }
        · status 缺省 200；body 是对象就按 JSON 回，是字符串就按 contentType 回
  ```

- ⚠️ **页面里不能用 `fetch('./api/xxx')`**：那条相对路径是相对**页面自己的目录**（`…/ui/`）解析的，
  会变成 `…/ui/api/xxx` 而落到静态文件那一条路上（404）。要按页面地址**算出通道前缀**：
  页面在 `/api/plugins/<类型>/<id>/ui/<入口>`，把 `/ui/…` 之后切掉再拼 `/api` 就是它 ——
  这样换 id、换类型都不用改（写法见任一源插件的 webui 顶部那段 `API` 常量）。
- ⇒ 页面里写 `fetch(API + '/xxx')` 就行。**面板不解析内容** ——
  插件想怎么设计自己的接口都行，插件的设置声明与存储也都在它自己那边（见下）。
- **调试台**：管理页可以手发一条动作（`POST /api/plugins/<类型>/<id>/call`），
  面板同样**不解释**动作与参数 —— 原样转过去、原样显示回来。
- **门禁**：webui 的静态资源与上面那条转发通道**默认都必须受面板登录门禁**；
  只有 `ingress` 名单逐路径声明了的，才能匿名（`public`）或凭外部访问令牌（`token`）放开
  （当前静态文件是免登录的，不能让插件的设置页变成公开页面）。
- ⚠️ **两个层级要分开**：**插件设置页**属于插件（管理它自己的实例）；
  **实例配置中心**属于实例。导航**不再给每个运行中的实例单独开子页**，收进插件的设置页内部。

## 十二、失败与诊断

- **失败如实**：插件报失败，面板如实记日志、如实空；不编造、不静默回退。
- **可选诊断字段**：插件返回里可以带诊断信息（如"这次含预热""内部等了多久"），
  面板**照实写进日志，但不参与打分**。`init` 这类内部逻辑搬进插件之后，
  那些"看不见的等待"需要留一条线索。
- **测速与超时**：站点级超时；连续失败的站点跳过一段时间、到期自动再试
  （沿用现有那套口径），勾选不受影响。

## 十三、参考：LuCI 插件怎么注册它的 web UI

OpenWrt 的 LuCI 插件（`luci-app-*`）是同类做法，可借鉴（来源：LuCI 仓库 `applications/luci-app-example`）。

| 路径 | 作用 |
|---|---|
| `/usr/share/luci/menu.d/luci-app-xxx.json` | **菜单声明** |
| `/usr/share/rpcd/acl.d/luci-app-xxx.json` | **权限声明**（能调哪些接口；不对就 "Access denied"） |
| `/www/luci-static/resources/view/xxx/*.js` | **前端页面** |
| `/usr/share/rpcd/ucode/xxx.uc` | 后端 RPC |
| `/etc/uci-defaults/80_xxx` | 首次安装时创建默认配置 |

菜单声明形如：

```json
"admin/example/form": {
  "title": "Form View",
  "order": 1,
  "action": { "type": "view", "path": "example/form" }
}
```

- **设置存哪**：`/etc/config/xxx` —— **插件自己的配置文件**，schema 由插件自己定，
  LuCI 不认识这些字段。
- **卸载**：菜单是**扫 `menu.d` 目录发现**的，没有中心注册表 ⇒ 删包时文件一起没 ⇒ 菜单项自动消失。

**借鉴三点**：入口是"文件声明 + 宿主扫描"；设置由插件自己存自己管；
权限要显式声明（对应本项目的"这些页面要登录才能看"）。

## 十四、与现有实现的对应

| 现在 | 之后 |
|---|---|
| 源的包在 `sources/`、清单在 `sources.json` | `plugins/<类型>/<id>/`，多类型统一 |
| 源跑在子进程、监听端口，面板用 HTTP 打它 | 插件跑在子进程，面板走**管道**、用**动作名**调用 |
| 猫源协议写死在面板（`core/catpaw.js` + agg 里几处 URL 拼接） | 收进**源插件**；面板只做"编辑参数 + 打分过滤" |
| 某个上游的元数据写死在面板（面板里带它的域常量与图片基地址） | 收进**元数据插件**；面板按域分派 |
| `agg.json` 里一套全局站点勾选与打分参数 | **模板**（站点 + 参数）按**域**选用 |
| 详情快照（小时级，判据"全站都通"） | **线路结果缓存**（按天默认 1 天，判据"有线路就存"） |
| 每个运行中的源各有一个「配置中心」子页 | 收进**插件设置页**内部 |
| 客户端拿到的播放地址由面板解析坐标后 302 | 面板把 `ref` 转给插件、插件回地址，面板仍只 302 |
| 源包在 `sources/`，逐个文件下载 + 一道 md5 | 插件包在 `plugins/<类型>/<id>/`，`tar.gz` + 两道 md5，装/卸/启停都走管理页 |
